# 文风记忆向量数据库（Style Memory DB）

提取、记忆、监控作者文风的专用向量库。目标：**让续写/改写保持"同一个人写的"质感，同时允许文风随剧情自然生长——防漂移，不防进化。**

与审稿库（review-vector-db）的关系：同属一个项目的 `.review-db/` 实例，文风数据存于独立子目录，互不干扰。

---

## 一、存储结构

```text
<小说项目根目录>/.review-db/
└── style/
    ├── style-profile.json        # 文风主档案：量化指纹 + 容差带 + 演变史指针
    ├── style-samples.jsonl       # 文风样本向量（每章1-3条代表性段落）
    ├── sentence-patterns.jsonl   # 句式指纹（高频句型骨架，去内容后）
    ├── lexicon.json              # 作者用词库：偏好词/禁用感词/口头禅/独特比喻
    └── style-evolution.jsonl     # 风格演变日志（每次指纹更新的增量与原因）
```

项目隔离、初始化时机、隔离铁律与审稿库完全一致（见 review-vector-db.md 第一节）：首次审稿随 `.review-db/` 一起初始化；无样本时文风维度跳过并声明。

## 二、文风指纹（style-profile.json）

从至少 3 章（建议 5 章以上）正文提取，样本不足时标注 `confidence: low`，只监控不判罚。

```json
{
  "db_version": 2.0,
  "book": "书名",
  "confidence": "high",
  "sampled_chapters": [1, 2, 3, 4, 5],
  "quant": {
    "avg_sentence_len": 14.2,          // 平均句长（字）
    "sentence_len_std": 9.8,           // 句长标准差（长短句交替幅度）
    "dialogue_ratio": 0.35,            // 对白占比
    "short_para_ratio": 0.62,          // 短段落（≤30字）占比
    "one_liner_ratio": 0.18,           // 单句成段占比（节奏 punch）
    "four_char_idiom_density": 0.004,  // 四字成语密度（个/百字）
    "adverb_density": 0.012,           // 副词密度
    "sensory_ratio": 0.15,             // 感官描写句占比（视/听/嗅/触/味）
    "inner_os_ratio": 0.22,            // 内心独白/吐槽占比
    "punct_flavor": { "破折号": 0.6, "省略号": 0.3, "感叹号": 0.4, "问号连击": 0.1 },
    "paragraph_rhythm": [3, 1, 5, 1, 8, 2, 1]  // 段落句数节奏模式（滑动窗口典型序列）
  },
  "qualitative": {
    "narrative_voice": "调侃式第三人称贴主角，内心吐槽毒舌、叙述嘴上克制",
    "humor_style": "反差吐槽 + 一本正经胡说八道，笑点多在OS不在对白",
    "description_habit": "重动作轻环境，环境描写≤两句必切回人物",
    "emotion_handling": "情绪不直写，用动作/生理反应外化（耳尖、指尖、喉结）",
    "transition_habit": "场景切换用空行+硬切，不用'与此同时'",
    "taboo_patterns": ["大段排比抒情", "'不是A而是B'连用", "结尾升华总结句"]
  },
  "tolerance_band": {                  // 容差带：超出才告警，避免风格硬化
    "avg_sentence_len": 0.25,          // ±25%
    "dialogue_ratio": 0.30,
    "short_para_ratio": 0.20,
    "idiom_density": 0.50,
    "inner_os_ratio": 0.35
  },
  "anchors": ["style-samples#s-001", "style-samples#s-005"],  // 标杆样本（最能代表文风的段落）
  "updated_at": "2026-08-31"
}
```

## 三、样本与向量

### 3.1 文风样本（style-samples.jsonl）

每章选 1-3 段**最能代表本书文风**的段落（非剧情关键段，而是声音特色鲜明的叙述/吐槽/对话段）：

```json
{
  "id": "s-018",
  "chapter": 6,
  "kind": "inner-os|narration|dialogue|action|sensory",
  "text": "原文段落（≤200字）",
  "vec": ["毒舌", "短句连击", "现代梗", "自我贬低", ...],   // 风格语义向量：描述"怎么写"而非"写什么"
  "quant_snapshot": { "句长均值": 11, "短段占比": 0.8, "OS占比": 0.5 },
  "is_anchor": false
}
```

### 3.2 句式骨架（sentence-patterns.jsonl）

去内容化的句型指纹（把名词/动词替换为槽位，保留结构）：

```json
{ "id": "p-007", "pattern": "【人物】本来想【动作】，结果【反转】。", "count": 12, "first_ch": 1, "last_ch": 9, "vec": ["反转句", "吐槽节奏"] }
```

高频骨架（count ≥ 5）= 作者的节奏签名；审稿时新章节若该用不用（节奏突变）或滥用（单一骨架占比 > 25%）都告警。

### 3.3 作者用词库（lexicon.json）

```json
{
  "pet_words": ["得，", "行吧", "好家伙", "——"],          // 高频偏好词/标点（文风签名，勿当冗余删）
  "signature_metaphors": ["像被踩了尾巴的猫", "CPU烧了"],  // 作者独特比喻库
  "avoid_feel": ["华丽辞藻堆砌", "翻译腔长定语", "古风腔"], // 与本文风冲突的语感
  "register": "现代口语+网络语感，禁止书面播音腔"
}
```

## 四、一致性监控（审稿时执行）

每章审稿生成该章的临时指纹，与 `style-profile.json` 比对：

1. **量化比对**：逐项算偏离率 = |本章值 − 档案值| / 档案值。
   - 偏离 ≤ 容差带 → ✅ 正常。
   - 超出容差带 → 🟡 文风漂移信号，需结合语境定性：
     - 剧情正当性（战斗章节句长变短、抒情章节OS变多属正常）→ 记录不判罚；
     - 无剧情理由的突变（突然播音腔、突然四字词堆砌、突然翻译腔）→ 🔴 判文风断裂，附 ❌原文 → ✅按档案声音改写示例 → 💡思路。
2. **质比对照**：`taboo_patterns` 在本章命中 → 🟡；`narrative_voice` 明显不符（如调侃文突然严肃说教）→ 🔴/🟡 视程度。
3. **样本相似度**：本章叙述段 vec 与 anchors 标杆样本语义比对，相似度 < 0.3 且无剧情理由 → 漂移告警。
4. **AI 味联动**：漂移信号常与 AI 腔伴生（排比/总结腔/四字词密度飙升同时出现）→ 与 A3 维度联动判罚，调度去 AI 味技能规则。
5. **伏笔自然度校验（v3.4.0，伏笔追踪专项联动）**：伏笔追踪专项（full/precise 档）命中伏笔句时，将伏笔句的临时量化指纹与本档案比对，判断伏笔是否符合作者整体文风：
   - 伏笔句**叙述腔突变**（`narrative_voice` 不符，如调侃文伏笔句突然严肃说教）或**修辞密度突增**（四字成语 / 排比密度超出容差带 2 倍）→ 判「伏笔伪装度不足」（🟡 生硬提示，归入【伏笔】前缀中优问题）；
   - **明示型伏笔密度 > 2 处/千字** → 判「过度直白、伪装度低」（🟡）；
   - 场景性变化（战斗 / 抒情 / 章末钩子章节的正当波动）→ 复用既有「剧情正当性」豁免，记录为演变候选，不判罚；
   - 校验**完全复用既有容差带与 EWMA 演变机制，不新增独立字段、不改原文风基准**；伪装度评级结果同步给伏笔专项附录（foreshadow-judgment-rules 埋设强度判定的佐证），文风维度不重复输出。

报告中文风维度输出：`🎨 文风指纹：偏离项 X/Y，最大偏离=句长 +38%（战斗场景，正常）；无理由漂移 0 处。`

## 五、动态演变机制（防风格硬化）

文风不是铁链。以下机制保证"随剧情自然长出来"：

### 5.1 指数滑动更新（EWMA）

每次审后回写，量化指纹按权重融合而非覆盖：

```text
新档案值 = 0.75 × 旧档案值 + 0.25 × 本章值（高置信阶段）
建档期（前5章）：0.4 × 旧 + 0.6 × 新（快速成型）
```

单章异常值（偏离 > 50%）不纳入融合，进 `style-evolution.jsonl` 挂起，连续 3 章同向漂移才确认为"演变"。

### 5.2 演变确认流程

`style-evolution.jsonl` 记录每次指纹变动：

```json
{ "chapter": 12, "change": "inner_os_ratio 0.22→0.31", "reason_candidate": "商战线开启，主角心理博弈增多", "status": "pending|confirmed|rejected", "confirmed_at": 15 }
```

- **pending（挂起）**：首次检测到持续漂移。
- **confirmed（确认）**：连续 3 章同向且有剧情支撑（副本/感情线/商战线等新阶段）→ 更新档案值与容差带，`qualitative` 补注演变方向。
- **rejected（驳回）**：漂移无剧情支撑或伴随 AI 腔 → 不更新档案，审稿时按旧指纹判罚。

### 5.3 容差带自适应

档案每次 confirmed 演变后，容差带按近 10 章实际波动的标准差重算（波动变大→容差自动放宽），避免"越写越不敢动"。硬性红线（`taboo_patterns`、`register`）不参与放宽。

### 5.4 人工锚点

作者可明确声明："这段就是我要的风格" → 该样本标记 `is_anchor: true`，锚点样本永不被滑动平均稀释；作者声明"这段不算数/是仿写"→ 该章不进指纹融合。**作者对文风的声明优先级最高**（与铁律2"刻意为之不算BUG"一致）。

## 六、使用边界

- 文风库用于**审稿判定与改写示范**：改写示例必须模仿档案声音（句长、口癖、节奏、吐槽方式），不得把作者的文字改成审稿 AI 的声音。
- 不输出"标准文风"——所有指纹都是**该作者自己的**历史统计，没有普适理想值。
- 建档期（<3 章样本）只描述、不判罚，避免用偶然章节锁死风格。
