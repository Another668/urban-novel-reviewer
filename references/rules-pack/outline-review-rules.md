# 大纲审稿专项规则（Outline Review Rules）

v3.2.0 新增。本文件是**大纲 / 卷纲 / 章纲 / 设定集**审稿的检查清单，由 SKILL.md「三、大纲审稿专项流程」加载。正文（已成稿章节）审稿不走本文件，仍走六步工作流。

---

## 0. 适用边界与输入识别

### 0.1 输入类型判断（语义解析层路由依据）

| 输入类型 | 判定信号 | 走向 |
|---------|---------|------|
| 大纲 / 总纲 | 文件名或内容含"大纲、总纲、剧情框架、故事梗概、开篇设定"；全书分卷/主线结构、核心设定综述 | 本文件（大纲审四步流程） |
| 卷纲 | "卷纲、第X卷、分卷大纲"；一卷（约 30-100 章）的剧情线与节点 | 本文件 |
| 章纲 | "章纲、章节大纲、第X章大纲、细纲"；单章或前几章的分场/情节梗概 | 本文件（章纲细化检查清单） |
| 设定集 | "设定集、世界观、设定文档、金手指设定、系统设定、人物设定"；规则/能力/势力/数值体系 | 本文件 + 视题材叠加 system-novel-rules |
| 系统设定专项 | 含"系统、面板、任务、奖励、签到、商城、属性点"等系统文要素的设定/大纲 | 本文件 + **system-novel-rules.md 必载** |

### 0.2 与正文审稿的边界

- 大纲审稿**不执行**：门禁 G1-G6（字数/对话占比/话疗/战斗/循环/节奏密度均针对成稿）、AI 味密度判定、文风指纹比对、`.review-db/` 向量库比对、text_stats 量化脚本。
- 大纲审稿**可复用**：记忆文档（大纲本身常就是记忆文档/真相文档，一致性以作者已确认的上位设定为准）、genre-classifier 题材识别（仅读前半部分，给出暂定结论）、silver 题材模板的雷区与必备元素。
- 用户拿"大纲 + 已写章节"混合输入时：大纲部分走本文件，章节部分走六步工作流，报告分区输出。

## 1. 审稿四步流程

### 第1步：前置识别（只读大纲前半部分）

不要求通读全部大纲，读取**核心设定 + 开篇卷纲 / 前 3 章章纲**即可，提取三项基础信息：

1. **基础分类**：男频 / 女频；篇幅（短篇 <20 万字 / 中篇 20-80 万 / 长篇 >80 万，或连载）；核心赛道（都市 / 玄幻 / 末世 / 科幻 / 古言 / 快穿等）。
2. **具体题材**：精准到细分类型（如 都市→系统神豪 / 职场日常 / 都市异能；玄幻→签到流 / 诸天流）。
3. **整体风格**：爽文 / 写实 / 轻松搞笑 / 严肃悬疑 / 慢热生活。

信息不足时给暂定判断，标注 `🟡 暂定分类：X，请确认`，不阻断审稿。

### 第2步：模板匹配（单次 ≤4 个）

按识别出的细分题材加载：
- silver 题材模板（`references/templates/`）1 个（取大纲视角的"必备元素 / 雷区"）；
- 命中系统文要素 → **必载 [system-novel-rules.md](system-novel-rules.md)**；
- 命中都市商战/职场 → 叠加 genre-matrix 都市矩阵；
- 命中特殊题材（克苏鲁/DND 等）→ 加载对应专项 agent。

### 第3步：专项审查（两类，都要做）

#### A. 基础逻辑审查（现状诊断）

| 维度 | 检查点 |
|------|--------|
| **设定自洽性** | 金手指/能力规则是否前后一致；世界观规则有无自相矛盾；数值体系（等级/货币/战力）有无明确定义；人物动机与设定是否匹配 |
| **剧情节奏** | 黄金三章是否有钩子/生死线；主线是否清晰（一句话能说清主角要什么、阻碍是什么）；卷与卷之间目标是否递进；有无明显的大段无冲突过渡 |
| **人物弧光** | 主角有无成长线（能力+认知双线）；反派动机是否成立（不能为坏而坏）；重要配角有无独立目标；感情线/友情线有无事件支撑 |
| **伏笔合理性** | 核心伏笔（身世/金手指来源/终局真相）有无埋设计划；已埋的钩子有无回收节点安排；是否有"挖坑不填"风险（列出埋设但无回收计划的伏笔） |

#### B. 前瞻风险审查（前瞻推演，v3.2 核心）

按大纲推演 **中期→大后期 3-5 个关键剧情节点**（如：首次实力跃升、第一次大反派对决、金手指升级/真相揭露、感情线确认、终局），逐节点预判：

- **剧情崩坏风险**：主线目标达成后无新目标（"无敌即烂尾"）；世界观扩大后主线失焦；多线叙事收束不了。
- **数值膨胀风险**：战力/资金/属性是否有明确上限曲线；后期是否只能靠"加设定"圆战力（系统文按 system-novel-rules 第 3 维度细查）。
- **人设 OOC 风险**：主角性格随实力增长有无崩坏路径（杀伐果断→滥杀、苟王→无脑冲）；反派降智空间；配角工具人化。
- **后期写崩风险**：金手指是否过早封顶；核心悬念（系统来源/身世真相）计划在多少比例处揭露；感情线/事业线终局有无着落。

每条前瞻预警必须写明：`推演节点（约第X章/第X卷）+ 触发条件 + 崩盘点 + 规避方向`，禁止空泛地说"后期可能崩"。

### 第4步：分层输出（三级建议 + 亮点）

固定输出三级，每级列 2-N 条：

1. **🔴 核心问题（必改项）**：不改会直接导致剧情崩坏 / 读者流失。每条写：问题 → 风险 → 修改方向（不代写）。
2. **🟡 优化建议（可选项）**：提升张力与合理性。每条写：现状 → 可优化方向。
3. **🔵 前瞻预警（风险点）**：当前无问题、后续大概率出问题。每条写：推演节点 + 触发条件 + 规避方向。
4. **✅ 亮点**：大纲中设计出色的点，不少于 2 条（审计是辅助不是否定）。

报告开头输出"审稿前提"：识别到的分类/题材/风格、加载了哪些模板、审到哪一卷/哪一章（未审部分声明"超出本次输入范围"）。

## 2. 章纲细化检查清单（输入为章纲时追加）

- **本章目标**：一句话能否说清本章推进了什么（剧情/人物/信息），无目标章=水文预备役；
- **冲突密度**：是否有至少 1 个明确冲突/转折；开篇 300 字内有无钩子承接上章；
- **章末钩子**：有无悬念/反转/新信息留客；
- **信息投放**：单章新增设定/人物是否 ≤3 个（信息轰炸风险）；
- **与卷纲对齐**：本章是否服务于本卷主线节点，有无偏离主线的支线章；
- **系统文章节**（叠加 system-novel-rules）：本章任务发布是否符合节奏（主线间隔≥10 章）、奖励是否匹配难度；系统言行是否符合其既定性格人设（对照 12 套性格模板防 OOC 突变，v3.2.1）。

---

## 3. 铁则

1. **只提建议、不改原文**：所有问题与风险标注等级、给出优化方向，**绝不直接改写大纲内容、不代写设定和剧情**（与正文审稿铁律 #4 同源）；
2. **建议必须挂节点**：核心问题引用大纲原文位置（"卷纲第X部分/章纲第X章"），前瞻预警必须写明推演节点与触发条件；
3. **不超范围审查**：用户只给了总纲就不评判具体章节写法；只给前 3 章章纲就不对后期细节下死结论（可给方向性预警并注明"待卷纲确认"）；
4. **作者已声明的设定不推翻**：与作者明确声明的核心设定冲突时，优先提示"该设定的连带风险"而非要求改设定（仲裁顺序同全局：记忆文档事实 > 作者声明 > 模板方法论）。
