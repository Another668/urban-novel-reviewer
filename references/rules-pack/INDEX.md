# 离线规则包索引（Rules Pack Index）

v3.0.0 起，9 个本机技能的核心规则从"调度引用"升级为**离线内置规则包**：本机技能存在时仍可 `[调度:技能名]` 标注来源，缺失时使用本目录内置副本，审稿流程不再依赖外部技能文件。v3.2.0 起新增**大纲审稿分支**（规划文档类输入不走正文六步流程）；v3.2.1 系统文专项规则**扩容为 20 类赛道模板 + 12 套系统性格人设模板**（机制/人设双校验 + 30/100/大结局前瞻推演）；v3.3.0 新增**性别转变角色专项**（性转/变嫁/女装大佬，心理-行为-生理-社交四维审查 + 6 套转变过程模板库 + 正文联动 C1/C2/C4）；v3.3.1 兼容方案升级：性别转变专项采用**插件式增量接入、零侵入原有核心**，明确三层路由 / 双重触发 + 置信度 <70% 自动降级 + 手动开关 / 通用规则优先级高于专项 / 建议级默认灰度 / 模块级回退清单；同时遵循 Trae 原生能力的**上下文继承**（性转参数与上一轮标准、深度、格式一同继承），全流程严格执行「**只提建议**、不改写原文」铁律，确保性转审稿是「原有审稿体系增强包」。v3.4.0 新增**伏笔追踪专项**（「剧情逻辑审查」深度增强插件，与系统文/性转专项平级、可任意叠加）：五大类 22 小类判定标准 + 伏笔全生命周期状态机（预埋→跟踪→回收→冲突校验，与 hooks 伏笔账同源同步）+ foreshadow_table 标准化台账跨章节继承 + 四类冲突校验 + 回收节奏与遗忘预警阈值 + 分题材伏笔模板 + 深度三档（quick/full/precise）+ foreshadow_base 可选精度对比；未命中伏笔需求时仅执行基础扫描、输出与原版本完全一致，全流程延续「**只提建议**、不改写原文」铁律。

## 统一调用接口（审稿流程中的加载规则）

1. 全审：5 个主规则包全部加载（ai-flavor / dialogue-game / character-logic / template-cliche / platform-gate）；
2. 指定维度审：按维度映射表只加载对应包（"只查 AI 味"→ ai-flavor；"只查对话"→ dialogue-game；"只查逻辑/人物"→ character-logic；"能发了吗"→ platform-gate + 全量）；
3. **大纲审分支（v3.2）**：输入为大纲/卷纲/章纲/设定集时，加载 outline-review-rules 走专项四步流程，不加载正文五主包、不跑门禁/12 维/向量库；命中系统文要素叠加 system-novel-rules；命中性别转变要素叠加 gender-transition-rules；强制型性转同时叠加两者；单次加载 ≤4 个文件；
4. **系统文正文联动（v3.2/v3.2.1）**：成稿章节含系统任务/奖励/数值/面板内容时，system-novel-rules 随 character-logic-rules 加载，数值穿帮判 D2、设计缺陷判 C2/C3；系统人格/语气突变、越界言行按 C2 判并对照 12 套性格人设模板做人设一致性检测（v3.2.1）；
5. **性别转变正文联动（v3.3.0）**：成稿章节出现性别转变场景、性别反差行为、周围人反应、身份暴露与重构、情感线推进等内容时，gender-transition-rules 随 character-logic-rules 加载；行为 / 心理穿帮与人格割裂判 C2，性别反差未利用 / 主线关联弱判 C4，设定前后不一 / 阶段跳步判 C1；强制型性转同时叠加 system-novel-rules；
6. 规则冲突仲裁：记忆文档事实 > 作者声明 > 平台规则（platform-gate）> 专项技能方法论（各 rules-pack）> 通用写作规律；性别转变专项额外遵循「**通用规则优先级高于专项规则**」：① 通用与专项无交集时各自独立判定；② 判定重叠时以通用结论为准；③ 通用规则已判定为「问题」的内容，专项规则**不再重复判定**，避免双重扣分与冲突输出。
7. 路由优先级四级排序（v3.3.1，防多专项冲突）：① 正文 / 大纲 / 设定集 类型判断；② 主题材匹配；③ 通用专项匹配（系统文等）；④ 细分专项匹配（性别转变等）。低优先级专项**永远不覆盖高优先级判定结果**。
8. 双重触发校验（v3.3.1，防误触）：性别转变专项启用需同时满足：① 命中性转类关键词；② 上下文确认为性转题材（出现性别转变情节/人物设定包含性别转换/作者明确要求性转专项审）。单一关键词不启用。
9. 自动降级 + 手动开关（v3.3.1）：性转置信度 **< 70%** 自动退回**通用人物审稿**（character-logic-rules），不加载 gender-transition-rules；作者可通过指令手动切换：「启用性转专项审查」/「禁用性转专项，按通用标准审」。
10. 模板叠加顺序（v3.3.1，主题材优先）：主题材模板（都市/末世/修仙等）→ 系统模板（如有）→ 性转插件模板；各模板负责各自维度，主题材模板永远作为基础标准，不被附加插件替代。
11. 灰度与数据隔离（v3.3.1）：性别转变专项默认设置为**建议级**（仅输出提示，不影响核心总分），稳定后可升级为**问题级**纳入核心评分；专项数据（扩展字段、向量、附录输出）独立存放于 `references/gender-transition/`（扩展模板占位）与 `.review-db/gender-transition/`（专项向量子目录），物理隔离，不污染原有库。
12. 模块级回退（v3.3.1）：需快速回退至 v3.2.1 功能集时，按【模块级回退清单】执行：① 删除 `gender-transition-rules.md`；② 删除本 INDEX 中 gender-transition 条目与上述 8–11 条兼容条款；③ 删除 SKILL.md 兼容层、审查模式行、附录意图词。
13. 输出兼容（v3.3.1）：性别转变专项命中时，在原报告结构末尾统一追加【专项审查附录】（含转变节奏评分 / 心理逻辑评分 / 行为细节评分 / 核心人设一致性校验四子段）；**未命中性转题材时输出与原来完全一致**，无多余内容；专项维度单独计分，不影响总分基准。
14. 规则包为检查清单，报告问题仍须引用原文 + 位置，禁止凭规则空判。
15. **伏笔追踪专项接入（v3.4.0，插件式增量）**：伏笔专项为「剧情逻辑审查」深度增强子插件，与系统文、性转专项平级（同为专项增强层模块），可任意叠加、互不覆盖；接入方式与 v3.3.1 性转一致——三层路由架构增量扩展（专项增强层新增伏笔追踪专项）、触发词追加至既有意图词典、复用六大支柱（复用对接见 SKILL.md §专项兼容层·伏笔追踪专项复用机制）、输出融入统一报告结构（问题标【伏笔】前缀、预警标【伏笔预警】、附录加伏笔追踪子段）。
16. **伏笔触发与档位（v3.4.0）**：① 伏笔类关键词命中 → 激活深度档；② 用户仅提「审稿」→ 默认执行基础伏笔检查（预埋识别 + 状态推进 + 明显冲突，不显示附录、输出与原版一致）；③ 自动叠加场景：新章正文审 / 大纲审 / 全文自检 / 系统文 / 性转专项审自动叠加基础伏笔校验；④ 深度档位直接继承审稿深度（快速→quick / 标准→full / 深度→precise），无需用户单独设置；⑤ 手动开关：「启用伏笔专项深度审查」/「禁用伏笔专项，按通用标准审」。
