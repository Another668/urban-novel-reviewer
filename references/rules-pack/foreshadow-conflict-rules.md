# 伏笔冲突校验规则包（v3.4.0 新增）

v3.4.0 新增。伏笔追踪专项的**冲突校验与节奏标准**子规则，与 [foreshadow-judgment-rules.md](foreshadow-judgment-rules.md)（判定标准）、[foreshadow-topic-templates.md](foreshadow-topic-templates.md)（分题材模板）配套使用。**本包为「剧情逻辑规则」下的伏笔专项规则子集**，插件式增量接入：通用剧情规则（character-logic-rules 的因果链 / 时间黑洞 / 读者契约）优先级高于本包，通用规则已判定的问题本包不重复输出，仅做伏笔维度的增量校验与台账预警。**设定联动**：冲突校验直接调用现有记忆文档（世界观 / 人物 / 体系设定）与向量库 facts / characters 记录，无需重复输入。

---

## 一、四类冲突校验

每类校验产出的问题按严重度分级（🔴 高优 / 🟡 中优 / 🟢 低优），引用格式统一为「台账 / 记忆文档第 X 条为 A，正文第 Y 段为 B」。

### 1. 设定冲突（联动 C3 世界观自洽 + facts.jsonl）

| 校验点 | 判定 | 级别 |
|--------|------|------|
| 伏笔兑现方式违反世界观规则（能力限制、力量来源、时空规则） | 检索 facts.jsonl 同实体记录，语义命中且结论相反 → 冲突 | 🔴 |
| 伏笔揭示的设定与记忆文档设定集矛盾 | 记忆文档优先，判正文 BUG（铁律 1）；作者声明演进除外，提示同步更新文档 | 🔴 |
| 力量体系类伏笔回收时凭空新增限制/豁免（F12-F15） | 台账无前置登记 → 吃书 | 🔴 |
| 伏笔回收使用的信息角色当时不可能获得 | 知识边界越界（联动人物档案） | 🟡 |

### 2. 人物冲突（联动 C2 人物塑造 + characters/ 档案）

| 校验点 | 判定 | 级别 |
|--------|------|------|
| 伏笔回收时人物态度与埋设期态度矛盾且无转变事件 | 对照 plots.jsonl 事件链找转变事件，找不到 → 反转无铺垫 | 🔴 |
| 同一伏笔，人物在埋设期「知道」、回收期「不知道」（记忆选择性问题） | 台账强化章记录 vs 正文表述冲突 | 🔴 |
| 人物类伏笔（F7-F11）揭示的身份与五维档案 / 关系槽位矛盾 | 档案优先，判正文 BUG；确认是设定演进才更新档案 | 🔴 |
| 埋设期角色对钩子的重视度与回收期不一致（埋时念念不忘、回收时毫不在意） | 无剧情理由 → 情绪承接断裂 | 🟡 |

### 3. 时间线冲突（联动 B2 时间线 + plots.slots.time）

| 校验点 | 判定 | 级别 |
|--------|------|------|
| 埋设时间与回收内容的时间逻辑矛盾（「二十年前埋下」的伏笔揭示出「十年前才存在」的事物） | 故事内时钟串联核对 | 🔴 |
| 特殊日期类伏笔（F6）到期未兑现且正文未交代 | 超期 + 契约违约 | 🟡 |
| 倒计时类伏笔的剩余时间与章节推进不符 | 每 5 章核对一次倒计时状态 | 🟡 |
| 预言类伏笔（F16）应验时机与预言表述的时机偏差 | 半应验记录为 half-closed，不判罚 | 🟢 |

### 4. 剧情自洽冲突（联动 B1 情节合理性 + B3 上下文连贯）

| 校验点 | 判定 | 级别 |
|--------|------|------|
| 回收方式与埋设暗示的方向完全不符（暗示身世之谜、回收成纯粹巧合） | 契约违背（读者契约四问联动） | 🔴 |
| 多方布局伏笔（F18）某方手牌蒸发，结局未交代 | 遗忘预警升级为冲突 | 🟡 |
| 半回收伏笔（half-closed）的余量悬念被静默遗忘 | 检查后续 30 章，无任何呼应 → 遗忘 | 🟡 |
| 正文回收了伏笔但台账无埋设记录（原生 hooks.jsonl 亦无） | 提示补登记，**不得当作矛盾判 BUG**（无记录 = 首次发现，与向量库检索纪律一致） | 🟢 |

## 二、回收节奏标准

伏笔价值 = 埋设质量 × 回收时机。按伏笔类型给出量化回收节奏（登记台账「计划回收章」时以此推定）：

| 伏笔类型 | 合理回收节奏 | 中途强化要求 | 超期判定 |
|---------|-------------|-------------|---------|
| 短伏笔（氛围级、单事件级，F20-F22 低优先级） | 埋设后 5-15 章内 | 无需强化 | >15 章未收 → 🟢 轻度超期 |
| 中伏笔（单卷级，F1-F4 / F7-F8 / F10-F11） | 单卷内 30-60 章回收 | 每 10-15 章提及一次防遗忘 | >60 章 open → 🟡 超期预警 |
| 长线伏笔（跨卷级，F5-F6 / F9 / F12-F15 / F18-F19） | ≤150 章（约 2-3 卷） | 每 20-30 章强化一次（reinforced） | 30 章无任何提及 → 遗忘预警 |
| 大结局级伏笔（核心谜底，F14 / F16 / F19 高优先级） | 最后 20 章前必须启动回收铺垫 | 每 30-50 章强化 + 每 100 章做一次「谜底距离评估」 | 距结局 <20 章仍未启动 → 🔴 高危 |

**回收节奏附加标准**：
- 单章回收密度 ≤3 条（高潮章 ≤5 条）：连续多伏笔回收 >5 条/章 → 信息倾倒式收尾，判 C1 节奏问题；
- 重大伏笔回收前后 1-2 章应有铺垫章（情绪/场景预热），裸回收 → 🟡 回收突兀；
- 回收兑现优先「半明/暗示」埋设（埋设越隐性、回收越有爽感）；明示型伏笔回收时必须补充增量信息（意外变量），否则判回收平淡（🟢）。

## 三、遗忘预警阈值

台账巡检时按以下阈值产出【伏笔预警】（标注于全局未回收统计与问题清单）：

| 预警类型 | 阈值 | 级别 |
|---------|------|------|
| 超期预警 | open 伏笔超过计划回收章（overdue） | 🟡 到期预警（正文离结局远时）/ 🔴（距结局 <30 章） |
| 遗忘预警 | open 伏笔连续 30 章无任何强化/提及（含半回收余量） | 🟡 高风险遗忘 |
| 深度遗忘 | open 伏笔连续 60 章无提及 | 🔴 列入核心问题清单 |
| 吃书预警 | closed 伏笔的回收内容与埋设内容矛盾（broken） | 🔴 核心问题（引用双方原文） |
| 台账膨胀预警 | 全书 open 伏笔 > 20 条（单卷 > 15 条） | 🟡 建议优先回收减负 |
| 大结局倒查 | 距大结局 <20 章，高优先级 open 伏笔仍未启动回收 | 🔴 前瞻风险（推演节点：结局前第 X 章） |

**吃书 / 前后矛盾专项**：吃书判定（broken）必须引用埋设原文与回收原文双锚点；大纲审时发现大纲规划的回收点与已写正文埋设冲突，按「记忆文档事实 > 作者声明」仲裁（铁律 1），判正文 BUG 并建议改正文。

## 四、与现有 D2 / hooks.jsonl 的联动（不重复判定）

- **分工边界**：D2 连载一致性维度的「伏笔账（5 状态机：open/half/closed）」继续由 hooks.jsonl 支撑，覆盖**超期未收**（🟡）与**closed 与埋设矛盾**（🔴）两项基础判定；伏笔专项在其上增量提供**五大类分类、隐性弱埋线识别、遗忘预警、回收节奏评估、精度对比**，输出统一进【专项审查附录】；
- **重叠处理**：hooks.jsonl 已判定的超期/矛盾问题，伏笔专项只做台账登记（补分类与回收计划建议），**不重复进入问题清单**（通用优先三原则）；
- **数据同源**：两账同源同步（judgment-rules §一回写纪律），检索时 hooks.jsonl 提供轻量状态、foreshadow_table 提供完整上下文，互为引用不出两套结论。

## 五、原生系统精度对比（foreshadow_base，可选）

用户传入原生伏笔系统输出（`foreshadow_base`）时执行（仅 precise 深度档）：

1. **数量对比**：原生识别 N 条 vs 本专项识别 M 条，重合 K 条；
2. **差异分析**：逐条标注本专项独有识别（多为隐性弱埋线 F20-F22、跨章长线类）与原生独有条目；
3. **采信建议**：重合条目以台账为准（有原文锚点）；本专项独有条目建议作者复核原文；原生独有条目登记入台账并标注 `source: foreshadow_base`；
4. 未传入 `foreshadow_base` 时**自动跳过**本环节，不影响其余任何功能（可选依赖）。

## 六、输出与降级规则

- **快速审稿（quick）**：仅输出高风险遗漏伏笔与明显冲突（超期 🔴 / 吃书 🔴），不输出完整追踪表；
- **标准审稿（full）**：输出【本章新增预埋】【全局未回收】【逻辑冲突】+ 台账更新摘要；
- **深度审稿（precise）**：全维度校验 + 精度对比报告（如有 base）+ 完整追踪表；
- **未命中伏笔类需求**：仅执行基础扫描（预埋识别 + 状态推进），不显示专项附录——**输出与原版本完全一致**；
- 所有冲突/预警问题均**只提建议**：回收时机建议、埋线方式调整、台账登记建议，不擅自改写原文。
