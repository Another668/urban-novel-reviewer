# 伏笔判定标准规则包（v3.4.0 新增，v3.6.0 扩充）

v3.4.0 新增；v3.6.0 扩充第六大类「公路场景专属伏笔」（F23-F27，克苏鲁向公路求生题材重点捕获），判定标准由五大类 22 小类升级为**六大类 27 小类**，状态机、台账字段与深度三档机制不变。**伏笔追踪专项**是「剧情逻辑审查」下的深度增强子插件（与系统文专项、性别转变专项平级），以插件式增量接入，**零侵入原有六大支柱与九大核心规则**，**通用规则优先级高于专项规则**：通用剧情逻辑规则（character-logic-rules）已判定的因果断裂 / 前后矛盾 / 设定遗忘问题，本专项**不重复判定**，只在伏笔维度做增量识别与台账化追踪。**三个加载入口**：

1. **大纲 / 设定稿加载**：审大纲 / 卷纲 / 章纲时自动叠加基础伏笔检查（校验伏笔节点规划、回收节奏、长线布局）；用户提到「伏笔 / 埋线 / 挖坑 / 填坑 / 回收 / 线索 / 闭环 / 剧情呼应」等关键词时加载本专项深度档；
2. **正文稿联动加载**：提交新章节正文审稿时自动执行基础伏笔检查（预埋识别 + 回收状态推进 + 冲突校验），命中伏笔类关键词升级深度档；
3. **全文 / 多章自检加载**：全文逻辑自检、多章对比审（跨章伏笔时间线）时加载，输出全书伏笔追踪表。

**深度档位映射（无需用户单独设置，直接继承当前审稿深度）**：

| 审稿深度 | 伏笔档位 | 执行内容 |
|---------|---------|---------|
| 快速审稿 | quick | 仅标记高风险遗漏伏笔、明显冲突（超期 + 吃书），不输出完整台账 |
| 标准审稿（默认） | full | 预埋识别 + 回收状态 + 冲突校验 + 基础台账更新 |
| 深度审稿 | precise | 全维度校验（6 大类 27 小类逐项）+ 原生系统精度对比（仅传入 `foreshadow_base` 时）+ 完整追踪表输出 |

**可选依赖**：`foreshadow_base`（用户原生系统的伏笔输出）为可选参数——未传入时自动跳过精度对比环节，核心功能独立完整运行。

## 一、伏笔全生命周期状态机

伏笔专项将伏笔管理拆为「预埋 → 跟踪 → 回收 → 冲突校验」四环节闭环，状态机与现有向量库 `hooks.jsonl`（open / half / closed 三状态）**同源兼容**，不建两套账：

| 专项状态 | 含义 | hooks.jsonl 映射 | 判定信号 |
|---------|------|-----------------|---------|
| planted（预埋） | 首次埋设，未被强化 | open | 出现新钩子信息且此前无记录 |
| reinforced（强化） | 中途再次提及/加深 | open（备注强化章） | 同一钩子语义再次出现 |
| half-closed（半回收） | 部分兑现，仍有余量 | half | 主线兑现但留有衍生悬念 |
| closed（回收） | 完整兑现闭合 | closed | 埋设内容被完整呼应/揭示 |
| overdue（超期） | 超过计划回收章仍 open | open + 超期标记 | 超过 `chapter_due` 未回收 |
| broken（冲突） | 回收内容与埋设矛盾 | closed + 矛盾标记 | 吃书 / 前后矛盾 |

**回写纪律**：每章审稿结束后，状态推进写入 `.review-db/hooks.jsonl`（轻量状态机，供 D2 连载一致性维度使用）与 `.review-db/foreshadow/foreshadow_table.md`（标准化台账，含完整分类与优先级字段），两处同源同步、一次回写，严禁只写一处造成账实分离。

## 二、六大类判定标准（27 小类）

识别正文 / 大纲中的伏笔时，先定大类，再定小类，登记进台账。**每条伏笔判定必须引用原文位置**（第X段 / 行号），禁止凭空登记。

### （一）实体类伏笔（6 小类）

| 小类 | 识别特征 | 判定要点 |
|------|---------|---------|
| F1 物品道具 | 特写描写、来历不明、赋予情感意义 | 出现时无用途说明、被「随手」带过但给了篇幅 = 埋设信号；有来历无去向 = 未回收 |
| F2 场景地点 | 反复出现或被刻意回避的场所 | 首次描写超常详细（超出场景功能所需）= 埋设；「以后再也别去那里」类禁令 = 强埋信号 |
| F3 书信文件 | 信件、日记、档案、合同、遗留笔记 | 内容被遮挡（未读完/被夺走/烧毁一半）= 半回收钩子 |
| F4 影像记录 | 照片、视频、录音、监控画面 | 画面中有异常细节但角色未注意 = 隐性埋线 |
| F5 遗留痕迹 | 伤口、疤痕、旧物、现场残留 | 与人物自述经历不符 = 高优先级伏笔（同时是 D2 线索） |
| F6 特殊日期 / 时间 | 被强调的纪念日、倒计时、约定日 | 「等到了那一天」承诺 = 硬性回收契约，到期未提 = 超期 |

### （二）人物类伏笔（5 小类）

| 小类 | 识别特征 | 判定要点 |
|------|---------|---------|
| F7 神秘身份 | 姓名来历、真实身份、隐藏地位 | 台词/行为与表面身份不符 = 埋设；身份揭示无铺垫 = 回收失败（判 B1） |
| F8 过往经历 | 角色回避谈论的历史、空白期 | 情绪异常反应（提及即变色）= 埋设信号 |
| F9 未登场人物 | 只被提及从未出场（已故/远方/传说） | 提及 ≥2 次且信息增量 = 长线伏笔，需登记回收计划 |
| F10 异常言行 | 不符合当前情境的台词、动作、选择 | 与人物五维档案对照，动机不充分 = 待回收伏笔（联动 C2） |
| F11 关系暗线 | 两人之间存在未言明的旧关联 | 称呼错位、眼神交流、过度回避 = 埋设信号 |

### （三）力量体系类伏笔（4 小类）

| 小类 | 识别特征 | 判定要点 |
|------|---------|---------|
| F12 能力限制 | 能力的边界条件、副作用、豁免场景 | 明确提及但从未触发 = 伏笔；临场新增限制 = 吃书（判 C3） |
| F13 代价机制 | 使用力量的代价（寿命/记忆/情感） | 代价延迟兑现 = 长线伏笔；代价凭空消失 = 冲突 |
| F14 体系层级 | 力量体系中的异常层级、被隐藏的等级 | 「不存在的那一阶」类描述 = 大结局级伏笔 |
| F15 规则例外 | 世界观规则中的特例、漏洞 | 拟人化/刻意强调的例外 = 布局信号（联动 C3 世界观自洽） |

### （四）剧情长线类伏笔（4 小类）

| 小类 | 识别特征 | 判定要点 |
|------|---------|---------|
| F16 预言谶语 | 谶语、梦、算命、剧透式台词 | 半应验 = half-closed；完全未应验且接近大结局 = 高危 |
| F17 悬念钩子 | 作者明示的未解之问 | 章末/卷末设问 = 契约性伏笔，需给出回收计划 |
| F18 多方布局 | 多个势力各自布局同一目标 | 各方手牌揭示完毕 = 长线回收完成；某方布局蒸发 = 遗忘预警 |
| F19 历史事件 | 世界观中的历史大事件、传说 | 传说与现状矛盾 = 核心揭秘型伏笔（常见于大结局） |

### （五）隐性弱埋线（3 小类，高精度识别重点）

隐性弱埋线是原生系统最容易漏判的伏笔形态——不占篇幅、不夺注意，但承载长线回收。**深度档（precise）逐句扫描，标准档（full）扫描场景级，快速档（quick）不主动识别**：

| 小类 | 识别特征 | 判定要点 |
|------|---------|---------|
| F20 细节异常 | 场景描写中与功能无关的细节 | 「描写冗余」即信号：不服务当前场景的五感细节（气味异常、摆设位置、天气反常）|
| F21 情绪伏笔 | 角色超出情境的情绪反应 | 无事件支撑的忧郁/警惕/怀念 = 内心伏笔，联动人物档案情绪反应库 |
| F22 口头承诺 | 对话中随口的约定、许诺、威胁 | 「等我回来」「下次让你好看」类台词 = 弱埋契约，需登记轻量台账 |

### （六）公路场景专属伏笔（5 小类，v3.6.0 新增，克苏鲁向公路求生题材重点捕获）

公路求生·克苏鲁向题材的伏笔高度依附「移动场景」——路标、载具、道路、节点、规则五类载体反复出现，是该题材最核心的氛围埋线与真相链载体。**命中公路求生题材（system-novel-rules #21）时，本类与 F20-F22 同属高精度识别重点：precise 档逐句扫描，full 档扫描场景级，quick 档不主动识别**。

| 小类 | 识别特征 | 判定要点 |
|------|---------|---------|
| F23 标识类 | 异常路牌、消失/重复的里程标、被涂改的指示牌、不存在的地名出口 | 路牌信息与实际里程/地图矛盾 = 埋设信号；被涂改/遮挡的地名 = 半明型强埋；重复出现的同一里程标 = 公路循环类核心伏笔（联动 B1 空间逻辑） |
| F24 载具类 | 车载收音机的诡异频段、后视镜里的异常影子、车辆自行启动/熄火、仪表盘的异常数字 | 仪表盘数字（油量/里程/转速）异常且角色未深究 = 半明埋设；收音机频段内容 = 规则类警告的主要载体（与 F27 互证）；后视镜影子无后续解释 = 未回收 |
| F25 道路类 | 永远走不完的直道、循环出现的参照物、路面的异常痕迹、凭空出现的岔路口 | 循环参照物（同一棵树/同一块广告牌第二次出现）= 公路空间扭曲级伏笔，需登记计划回收章；凭空岔路的选择 = F17 悬念钩子同源，须有后续兑现 |
| F26 节点类 | 服务区的异常告示、加油站不存在的编号、隧道里的回声、废弃车辆里的遗留物 | 节点编号矛盾（如连续两个"第 3 号加油站"）= 强埋信号；废弃车辆遗留物（日记/照片/行车记录仪）= F3/F4 同源实体伏笔，按公路场景优先归类本小类；隧道回声内容 = 规则/警告载体 |
| F27 规则类 | 不知来源的行车守则、收音机里的警告、前人留下的便签、重复出现的禁忌提示 | 规则条文本身 = 契约性伏笔，违反后的结果必须与条文暗示呼应（无呼应 = 伪规则，判 C3）；同一禁忌经不同载体（路牌/收音机/便签）重复出现 = reinforced 强化登记；规则的「为什么」指向公路本质真相 = 大结局级回收 |

**公路伏笔回收节奏提示**：标识/载具/道路类（F23-F25）以短中线为主（节点内或跨 1-2 个节点兑现，5-30 章）；节点遗留物类（F26）中线为主（30-60 章，随公路推进拼合真相）；规则类（F27）为长线骨架（≤150 章，每 20-30 章随新规则解锁强化，大结局级揭示公路本质）。

## 三、埋设强度与伪装度判定

复用文风记忆库（style-memory-db）的作者文风指纹，校验伏笔是否**写得过于生硬**（伪装度不足）：

| 强度 | 表现 | 判定 |
|------|------|------|
| 明示型 | 直接点明「这件事很奇怪」「他一定有秘密」 | 🟡 过度直白，读者预期拉满，回收时缺乏惊喜；密度 >2 处/千字判伏笔生硬 |
| 半明型 | 给出异常但角色不深究 | ✅ 标准埋设强度（推荐主力） |
| 暗示型 | 融入场景/动作/对话，需读者主动捕捉 | ✅ 高质量埋设（回收爽感最强） |
| 隐性型 | F20-F22 弱埋线 | ✅ 长线布局形态，但需台账登记防遗忘 |

**文风自然度校验规则**（复用作者文风指纹，不改写原文风基准）：
- 伏笔句与作者整体叙事风格偏离（叙述腔突变、修辞密度突增）→ 🟡 伏笔伪装度不足，提示调整埋线方式；
- 「为埋而埋」的冗余细节（与 F20 区分：F20 需与后文呼应，孤立冗余只是水字数，判 A1 冗余而非伏笔）——**判定前先查台账与后文，无呼应线索的疑似埋设标记为待验证，不直接计入台账**。

## 四、标准化台账字段（foreshadow_table）

台账存于 `.review-db/foreshadow/foreshadow_table.md`（Markdown 表格，可直接存档 / 打印 / 复制进作者自己的记忆文档），每行一条伏笔：

| 字段 | 说明 |
|------|------|
| 编号 | F-001 顺序编号（跨章递增，不重号） |
| 大类 / 小类 | 六大类之一 + 27 小类编号（如：实体类 F1 物品道具；公路场景专属类 F23 标识类） |
| 内容摘要 | ≤30 字的钩子描述 |
| 埋设章 / 强化章 | 首次埋设章号 + 历次强化章号 |
| 计划回收章 | 按回收节奏标准推定的合理回收区间（见 conflict-rules §二） |
| 状态 | planted / reinforced / half-closed / closed / overdue / broken |
| 优先级 | 高（契约性/大结局级）/ 中（主线级）/ 低（氛围级） |
| 原文锚点 | 埋设句摘录 + 章号段落位置（强制，无锚点不入账） |
| 预警 / 冲突 | 超期、遗忘、吃书记录（无则留空） |

**台账持久化与继承**：每章审稿后自动更新；下一次审稿（下一章 / 多章 / 全文自检）第1步自动读取全局台账，实现跨章节连续追踪——台账随项目 `.review-db/` 走，不随技能分发，与现有隔离铁律一致。

## 六、冲突仲裁与铁则

1. **通用优先**：character-logic-rules / review-vector-db 已判定的因果断裂（B1）、设定遗忘（B3）、事实矛盾（C3）、伏笔超期（D2）问题，本专项不重复输出，只在附录中做台账登记与回收计划补充；
2. **只提建议**：对伏笔的埋设与回收只输出诊断、预警与优化方向（回收时机建议、埋线方式调整），**不擅自改写原文、不代写伏笔剧情**；
3. **判定必须有出处**：每条伏笔指控引用「台账第 F-XXX 条记录为 A，正文第 Y 段写为 B」格式，与铁律 5 一致；
4. **可选依赖不阻塞**：`foreshadow_base` 缺失时跳过精度对比，其余功能完整。
