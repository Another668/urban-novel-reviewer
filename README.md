> 网文创作的综合性质量控制工具：**正文审稿（前置语义解析层 + 记忆文档 + 审稿向量库 + 文风记忆 + 规则包）+ 大纲/卷纲/章纲/设定集专项审稿（前瞻风险预警）+ 系统文专项规则库 + 性别转变角色专项 + 伏笔追踪与全链路校验专项 + 公路求生·克苏鲁向题材适配 + v3.7.0 三级更新分级机制（轻量默认减 60%~75% token）+ v3.9.0 轻量记忆索引体系（超长篇审稿再省 50%+ 回溯 token）**，支持男频/女频全题材 21 类。

## 📌 最新更新（v3.9.0 · 2026-09-05）

本次更新的核心：**轻量记忆索引体系**——针对超长篇（>100 章）审稿的记忆回溯瓶颈，用"确定性结构化索引"替代"语义检索/正文回溯"，在审稿效果不变的前提下，超长篇审稿再省 **50%+ 回溯 token**。

### 1. 设计原理：确定性查表替代语义检索

审稿中 90% 的一致性核查查询本质是确定性查询（"某人物/物品/伏笔在哪章、什么状态"），结构化索引可精确命中，比向量化方案轻一个数量级：

| 维度 | 向量化方案 | 结构化索引方案 |
|------|-----------|--------------|
| 检索过程 | 计算相似度→排序→比对 | 精确查表→直接命中 |
| Token 消耗 | 建库费 + 检索费 | 建库极便宜 + 检索几乎免费 |
| 可解释性 | 黑盒 | 人可直接阅读维护 |
| 误判率 | 语义可能跑偏 | 零误判（精确匹配） |

### 2. 四大索引模块

| 索引文件 | 功能 | 体积控制 |
|---------|------|---------|
| `entity_index.json` | **实体注册表**：人物/物品/势力/地点名片行，检索总入口 | 一实体一行，key_facts ≤5 条 |
| `characters/` | **分层人物库**：重要配角（出场≥3章）独立建档，出场才读 | 每人 ~40 行 |
| `keyword_index.json` | **倒排索引**：关键词→章节列表，伏笔定位/事件回溯 | 单词保留最近 30 章，总量>500 裁剪 |
| `story_summaries.json` | **滚动摘要**：最近10章详情 + 每20章 arc 摘要 + 全局简介 | **总量恒定 ~200 行**，不随章节数膨胀 |

### 3. 人物卡三级金字塔

```
常驻层（setting.md）：主角 + 核心配角前5 → 每次必读，setting.md 控制在 ~300 行内
建档层（characters/）：出场≥3章的重要配角 → 本章出场才读
名片层（entity_index.json）：边缘角色一行名片 → 临时提取补充
```

超长篇 setting.md 不再随人物增多无限膨胀；配角出场满 3 章提示建档（/sync-setting 执行）。

### 4. 题材缓存路由

- `meta.json` 新增 `cached_genre` 字段：首次识别后缓存题材+模板清单
- 第二次起审稿：5-8 个强信号快速校验替代全量打分，**每次省 ~150-200 token**
- 题材漂移检测兜底：校验失败自动回退完整识别，报告标注漂移警告

### 5. 与三级更新分级的整合

索引维护全部为**增量追加**（实体计数+1 / 关键词追加 / 摘要追加），纳入既有三级更新分级：
- **轻量级（默认）**：索引自动维护，<150 token，无需用户指令；
- **标准级（/sync-setting）**：+ 人物卡建档 + key_facts 更新；
- **全量级（/sync-outline）**：+ arc 精合并 + 死实体归档 + 晋升/降级。

### 6. 兼容性

- **旧库零迁移**：v3.7/v3.8 结构的项目库不强制迁移，审稿时惰性补建索引，下次审稿生效；
- **审稿效果零衰减**：所有审查维度、判定标准完全不变，只是数据获取路径更短；
- **常驻加载恒定**：~300-500 行，不随章节数膨胀（对比超长篇回溯正文的数千行）。

## 📌 历史更新（v3.7.0 · 2026-09-05）

本次更新的核心：**三级更新分级机制 + 记忆文档整合精简**——以「无明确指令，绝对不自动修改章纲、卷纲」为核心原则，砍掉默认模式下所有非必要的文档联动修改，仅保留最轻量的状态更新（<100token）；只有用户明确发指令时，才同步更新章纲、卷纲和全量记忆文档。同时将项目数据库从 10+ 个文件压缩到 5 个核心文件，所有更新严格执行增量写入，避免全量重写浪费 token。默认轻量模式相比原全量联动模式减少 **60%~75%** 额外 token 消耗，完全兼容 v3.6 架构——所有原有专项、模板、规则全部可用，只是更新逻辑更克制。

### 1. 三级更新分级机制（从根源减少联动）

**核心原则**：无明确指令不自动修改章纲、卷纲；改到什么范围，就更新对应范围的记忆数据，绝不全量联动。

| 更新等级 | 触发条件 | 更新范围 | 额外 token 消耗 |
|---------|---------|---------|--------------|
| **轻量级（默认）** | 用户仅提交正文修改 / 普通审稿，无额外指令 | 1. 更新 meta.json 当前章节号<br>2. 仅更新涉及到的伏笔状态（回收/新增）<br>3. 增量追加文风指纹<br>**绝对不碰**：章纲、卷纲、setting.md、project_state.json | 极低（<100token） |
| **标准级** | 用户指令：`/sync-setting` / 「同步更新设定」 | 包含轻量级全部内容<br>+ 增量修改 setting.md 对应人物/世界观段落<br>+ 更新 project_state.json 对应专项字段<br>**仍不碰**：章纲、卷纲 | 中（仅修改涉及段落） |
| **全量级** | 用户指令：`/sync-outline` / 「同步更新章纲/卷纲」 | 包含标准级全部内容<br>+ 同步重写对应章纲<br>+ 联动修正卷纲剧情节点<br>+ 全量校验全局记忆一致性 | 较高（按大纲篇幅） |

**严格禁止的自动行为**：① 禁止根据正文修改自动反向推导修改章纲、卷纲，必须用户主动发指令才执行；② 禁止修改一小段正文就全量重写整个设定文档、整个状态库；③ 禁止未触发对应专项时，更新该专项的记忆数据。

### 2. 记忆文档整合精简（减少文件读写次数）

把原拆分过细的多个记忆文档合并压缩，减少文件数量，单次读写覆盖更多维度，避免反复读写多个文件浪费 token。

**整合后项目数据库结构**：
```
$WORKSPACE_FOLDER/.review-db/
├── meta.json              # 项目元数据（极轻量）：书名、题材、当前章节、模块标记
├── setting.md             # 单文件包含世界观+人物卡+力量体系，按段落分区
├── project_state.json     # 全专项状态合并：system_state / gender_state / road_state / san_value
├── foreshadow/
│   ├── index.json         # 伏笔轻量索引：FID+状态+章节，日常仅读这个
│   ├── details/           # 单条伏笔详情，按需读写
│   └── archived.json      # 已回收归档，日常不碰
└── style_fingerprint.json # 仅保留文风指纹，其余向量临时计算不持久化
```

**三大精简动作**：
- **砍掉冗余向量库**：人物、剧情、对白、数值等向量不持久化存储，每次审稿临时从正文 + 设定中提取，审完即弃；
- **专项状态合并**：所有专项的状态数据合并到 `project_state.json` 一个文件，读写一次覆盖所有专项，不用每个专项单独读文件；
- **设定文档单文件化**：世界观、人物、力量体系合并到 `setting.md`，按标题分区，增量更新时只改对应段落，不重写全文。

### 3. 增量写入规则强化（避免全量重写）

所有更新严格执行「增量修改」，只改命中的行/条目，不重写整个文件：

| 文件 | 增量写入规则 |
|------|------------|
| setting.md | 按标题定位，仅替换涉及的人物/世界观段落，其余内容原样保留 |
| foreshadow/index.json | 新增伏笔仅追加新条目；状态更新仅修改对应 FID 的状态字段；归档仅移动对应条目 |
| project_state.json | 仅更新对应字段，其余字段原样保留；未触发的专项绝对不触碰 |
| style_fingerprint.json | 按 EWMA 指数滑动更新，仅修改量化字段值，不重写全文 |
| archived.json | 默认不触碰，仅手动指令触发归档操作 |
| meta.json | 每次审稿后更新当前章节号，其余字段仅在初始化/题材重识别时更新 |

### 4. 手动控制指令集（新增 3 条，累计 8 条）

| 指令 | 功能 | 使用场景 |
|------|------|----------|
| `/sync-setting` | **标准级更新**，同步修改对应设定文档（setting.md + project_state.json），不碰大纲 | 本章有重要设定变动（人物成长、世界观补充、数值更新），需要同步写入设定文档时 |
| `/sync-outline` | **全量级更新**，同步更新章纲、卷纲与全量记忆文档 | 正文改动较大，需要联动更新章纲、卷纲、设定、伏笔台账时 |
| `/force-archive` | 手动归档已回收伏笔，清理索引体积 | 每完成一卷或重大剧情线后执行，减少后续审稿的数据库加载量 |

> 原有 5 条指令（/init-review /full-load /light-mode /archive-closed /export-foreshadow）全部保留，`/archive-closed` 与 `/force-archive` 功能等价。

### 5. 兼容与落地效果

- **日常审稿改文**：默认轻量模式，只做审稿输出 + 伏笔状态微调 + 文风指纹更新，几乎没有额外的文档修改 token 消耗；
- **需要同步大纲时**：用户加一句 `/sync-outline`，才执行全量联动，避免无意识浪费；
- **文件数量减少**：核心读写文件从 10+ 个压缩到 5 个，减少多次 IO 的 token 开销；
- **完全兼容**：所有原有专项、模板、规则全部可用，只是更新逻辑更克制；未命中新指令时输出与 v3.6.0 完全一致（仅内部数据读写路径变化，用户无感知）；
- **模块级回退**：删除 SKILL.md 中 v3.7.0 更新分级章节、review-vector-db.md 精简策略章节、style-memory-db.md 精简说明、INDEX.md 对应条款，即可回退至 v3.6.0 架构。

## 📌 历史更新（v3.6.0 · 2026-09-04）

> v3.6.0 历史条目已顺延为本节，公路求生·克苏鲁向题材适配功能不变，v3.7.0 仅升级数据读写与更新分级机制。

本次更新的核心：**公路求生·克苏鲁向题材专项适配**——针对「移动载具 + 线性公路节点 + 资源消耗逻辑 + SAN 认知污染」的交叉题材，以**增量式、零侵入**方式补充 1 套细分赛道模板、1 大类专属伏笔、2 组专属校验规则与触发词，自动接入既有三层路由与伏笔追踪闭环。通用审稿、系统文基础校验、数据持久化、按需加载机制全部不变；未命中公路/克苏鲁要素时输出与 v3.5.0 完全一致。

### 1. 系统文赛道模板库 20 类 → 21 类（新增公路求生·克苏鲁向）

`system-novel-rules.md` 新增第 21 套赛道模板，与既有「末世求生系统」「诡异/克苏鲁系统」模板**三重叠加**校验，覆盖六大合理设定维度：

| 维度 | 核心校验点 |
|------|-----------|
| 载具核心机制 | 初始载具符合末世设定且有耐久/油耗/载重属性；升级严格绑定节点奖励、梯度解锁；故障修复零件必须来自搜刮/任务奖励，**禁止凭空修复**；载具意识必须逐步觉醒 |

- **任务发布机制**：主线/支线/日常三级梯度；主线间隔 ≥10 章、支线 3-5 章 1 个；可选任务占比 ≥60%；禁止跨阶段发布；
- **奖励体系**：功能→成长→核心级梯度；强度与难度正相关；所有奖励带限制（场景/冷却/副作用）；前期数值不超过世界观上限 10%；
- **系统本身设定**：工具属性禁止过度人格化；系统升级线与主角同步；必须有终极目标（防烂尾）；保留信息差（防无悬念）。

**八大类型模板库**（审稿对标基准）：签到流、神豪流、职业/技能流、末世求生流、诸天穿梭流、种田经营流、攻略/好感度流、属性加点流——每类含合理设定标准、常见崩盘点、逐项校验清单（如神豪流开局资金 10 万-100 万、签到流都市日常奖励 ≤10 万元、末世流禁开局重火力）。

### 3. 解析层与铁律扩展

## 审稿维度

### 基础 12 维

```text
A. 文字层
  A1 文字基础      病句 / 错别字 / 流水账 / 形容词堆砌 / 冗余
  A2 重复雷同      高频词 / 同义重复 / 情绪反应克隆（本章临时提取情绪反应指纹比对）
  A3 AI 痕迹       AI 腔套话 / 句式模板 / 总结腔 / 机关枪节奏

B. 逻辑层
  B1 情节合理性    动机充分 / 因果链 / 上帝之手（story_summaries 事件链检索）
  B2 时间线        时序 / 年龄 / 季节 / 故事内时钟
  B3 上下文连贯    设定遗忘 / 情绪突变 / 状态承接
  B4 视角一致      POV 越界 / 读心 / 无预告切换

C. 体验层
  C1 节奏爽点      拖沓 / 爽点密度 / 章末钩子 / 开篇吸引力
  C2 人物塑造      性格一致(OOC) / 语言指纹 / 成长弧（人物档案+本章临时提取对白指纹比对）
  C3 世界观自洽    规则一致 / 能力代价 / 势力关系（setting.md 设定+entity_index 实体名片比对）
  C4 对话质量      同质化 / 功能化 / 潜台词 / 动作锚定（口语化+千人一面检索）

D. 专项层
  D1 人情世故      社交段位 / 分寸感 / 利益逻辑 / 话留余地
  D2 连载一致性    数值穿帮 / 伏笔账 / 物品技能账 / 任务账（索引层优先比对 + 本章数值逐项核对 + foreshadow/index.json 状态机）
```

另加 **文风维度**（🎨 文风指纹）：量化指标容差带比对 + 质化声音一致性。

**计分方式**：基础 12 维均分 × 0.70 + 题材专项均分 × 0.30

| 综合分 | 评级 | 发布建议 |
|--------|------|----------|
| 8.5–10 | 🟢 优质 | 可直接发布 |
| 7.0–8.4 | 🟡 良好 | 修高优问题后可发 |
| 5.5–6.9 | 🟠 及格 | 修高优 + 中优后发布 |
| 4.0–5.4 | 🔴 待改进 | 暂缓发布 |
| 0–3.9 | ⚫ 需大改 | 建议重写 |

## 审稿向量数据库

详见 [references/review-vector-db.md](references/review-vector-db.md)。

- **位置与隔离**：`<小说项目根目录>/.review-db/`，一书一库；首审自动初始化（报告注明 `🆕 已初始化独立审稿数据库`），项目 ID 校验防串库；删除目录即可"忘记项目"，下次审稿自动重建。
- **结构（v3.9.0 轻量记忆索引体系）**：`meta.json`（项目元数据 + `cached_genre` 题材缓存路由）、`setting.md`（核心设定单文件，~300 行内）、`project_state.json`（全专项状态合并单文件）、四大结构化索引——`entity_index.json` 实体注册表 / `characters/` 分层人物库 / `keyword_index.json` 倒排索引 / `story_summaries.json` 滚动摘要、`foreshadow/`（index.json 索引 + details/ 详情 + archived.json 归档）、`style_fingerprint.json` 文风指纹。
- **检索**：**确定性查表替代语义检索**——人物/物品/势力/伏笔查询直接命中实体注册表名片行、倒排索引章节列表与滚动摘要；超长篇常驻加载恒定 ~300-600 行，回溯 token 预计再省 50-60%。
- **向量临时提取（v3.7.0 起）**：社交/人物/剧情/对白/数值等向量审稿时从正文 + setting.md 临时提取，审完即弃，不持久化。
- **三大功能**：
  - 剧情逻辑：事件 cause 无前置=因果断裂；事实陈述与已确认事实相反=事实矛盾；跨章 result 不承接=承接断裂（D2 连载一致性：索引层优先，缺失时才回溯正文）；
  - OOC：违反灵魂铁则=🔴；语言指纹漂移、情绪反应连续 3 次克隆=🟡；成长弧方向变化进"成长候选"不误判；
  - 对白：书面腔、同台两人指纹相似度 >0.7（千人一面）、≥4 轮无动作锚定（飘对话）、台词复述剧情（信息倾倒）。
- **回写纪律**：全部增量写入（禁止全量重写，按三级更新分级控制范围）；事实类只追加不覆盖，冲突保留 `superseded_by` 可追溯；全部明文存储，可人工查阅纠错。

## 文风记忆数据库

详见 [references/style-memory-db.md](references/style-memory-db.md)。

- **指纹构成**：量化（句长均值/标准差、对白比、短段比、单句成段率、成语密度、副词密度、感官占比、OS 占比、标点口味、段落节奏序列）+ 质化（叙述声音、幽默方式、描写习惯、情绪处理、转场习惯、禁忌模式、偏好词/签名比喻/语域）。

## 记忆文档索引系统

审稿前**强制**建立记忆底座，不凭章节内文空判：

1. **自动扫描**：真相文档（`*真相*`、`*记忆*`、`story_bible.md`、`current_state.md`、`pending_hooks.md`）、大纲（`大纲/`、`*卷纲*`）、社交设定（`setting/character_social.md`、`relationship_map.md`）、正文章节；
2. **首审灌库**：扫描到的人物/事实/数值/伏笔首次写入 `.review-db/`；
3. **提取本章锚点**：出场人物五维档案 + 灵魂铁则 + 语言指纹、数值前值、在途任务、持有物品、已解锁技能、伏笔账、已确认事实红线、大纲节点目标；
4. **六组核验清单**：数值核验 / 人物核验 / 物品技能核验 / 伏笔核验 / 已确认事实核验 / 时间线核验；
5. **文档滞后处理**：记忆文档落后于被审章节时自动告警，切换"正文回溯 + 索引层"顺推核对，审后输出待更新清单。

每条穿帮指控必须写明：**"记忆文档/伏笔索引第 X 条记录为 A，正文第 Y 段写为 B"**。

## 报告输出

审稿报告包含：

- 🧠 **记忆底座**：库实例状态（新建/已有）、引用文档、核对数值伏笔、加载模板、调度技能
- 🎨 **文风指纹**：档案置信度、量化偏离项、最大偏离及剧情理由判定、演变挂起项
- 📊 **综合评分表**：12 维 + 题材专项逐项 0–10 分 + 加权总分 + 评级
- 🔴 **高优问题**（3–5 条）：硬伤穿帮，每条附 ❌原文 → ✅建议 → 💡思路
- 🟡 **中优问题**（3–6 条）：有损质感
- 🟢 **低优问题**：打磨项
- 📈 **连载一致性核对表**：数值 / 伏笔 / 物品 / 人物 / 事实逐项对照（注明向量库记录出处）
- ✅ **亮点记录**：写得好的段落（不少于 2 条）
- 📝 **审后回写清单**：向量库自动回写项 + 待作者确认项（新事实/成长候选/文风演变/记忆文档同步）
- 📌 **审稿总评**：2–4 句综合结论

## 设计原则

1. **记忆文档是最高事实源**——正文与文档/向量库冲突判正文 BUG；作者明确改设定除外
2. **"刻意为之"不算 BUG**——角色口癖、设定好的反差、作者声明的锚点风格不误判
3. **AI 味看密度不看单次出现**——排比、四字词短段反复堆叠才判
4. **不擅自续写、不大幅改写**——只给可落地建议和示例句，改写用作者自己的文风声音
5. **数值 / 伏笔判断必须有出处**——每条指控附文档/向量库 vs 正文对照
6. **项目数据严格隔离**——一书一库，技能与数据分离，跨设备随项目迁移
7. **防漂移不防进化**——文风有容差带，确认的自然演变更新档案，不锁死作者声音
8. **审计是辅助不是否定**——亮点必须指出
9. **大纲/设定只提建议不改原文**——大纲审只输出问题诊断/风险提示/优化方向，绝不改写大纲内容、不代写设定剧情；前瞻预警必须挂推演节点，不超输入范围下死结论
